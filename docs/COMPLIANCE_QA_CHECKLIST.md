# InvoiceFlow — Checklist לבדיקות קבלה לפני הגשה

> המסמך הוא checklist פנימי. הוא אינו מהווה אישור או רישום של התוכנה.

## 1. מסמכים והפקה

- [ ] מסמך חדש מתחיל כטיוטה.
- [ ] מסמך שהופק אינו ניתן לעריכה.
- [ ] מסמך שהופק אינו ניתן למחיקה.
- [ ] ביטול דורש סיבה ונשמר עם המסמך.
- [ ] חשבונית זיכוי מקושרת למסמך המקורי.
- [ ] שינוי סטטוס אינו מאפשר החזרה לטיוטה.
- [ ] שורות של מסמך שהופק אינן ניתנות לשינוי.

## 2. מספרים

- [ ] מספר מסמך אינו משתנה לאחר ההפקה.
- [ ] שתי הפקות מקבילות אינן מקבלות אותו מספר.
- [ ] כשל בהפקה אינו מסמן מסמך כהופק.
- [ ] רצף המספור נשמר לאחר רענון/הפעלה מחדש.

## 3. מספר הקצאה

- [ ] חשבונית מס החייבת במספר הקצאה לא מופקת ללא מספר שהתקבל בפועל.
- [ ] מספר הקצאה מוצג רק כאשר נשמר במערכת.
- [ ] כשל בשירות חיצוני אינו יוצר מספר הקצאה פיקטיבי.
- [ ] סף החובה ניתן לעדכון בהתאם להוראות רשות המסים העדכניות.

## 4. סוג העסק ומע״מ

- [ ] עוסק פטור אינו יכול להפיק חשבונית מס.
- [ ] שיעור מע״מ אינו יכול להיות שלילי או מעל 100.
- [ ] חישובי subtotal / VAT / total עקביים.

## 5. אבטחה והרשאות

- [ ] משתמש מעסק A אינו יכול לקרוא נתונים של עסק B.
- [ ] משתמש מעסק A אינו יכול לשנות נתונים של עסק B.
- [ ] משתמש רגיל אינו יכול להעניק לעצמו הרשאת admin/owner.
- [ ] פעולות רגישות מתבצעות בצד שרת ולא מסתמכות על ערך שמגיע מהלקוח.
- [ ] secrets של אינטגרציות אינם נמצאים בקוד צד לקוח.

## 6. Audit וראיות

- [ ] הפקת מסמך יוצרת audit event.
- [ ] ביטול מסמך יוצר audit event.
- [ ] שינויי סטטוס רגישים נרשמים.
- [ ] audit אינו ניתן למחיקה/שינוי דרך ממשק המשתמש.
- [ ] הראיה נשמרת גם אם המשתמש מרענן את הדפדפן.

## 7. Uniform Format

- [ ] קיימת שכבת export נפרדת מה־UI.
- [ ] אין schema שהומצא במקום המפרט הרשמי.
- [ ] הייצוא עובר validation לפני שהוא מסומן כמוכן להגשה.
- [ ] נבנה dataset בדיקה מתאים לסימולטור הרשמי.
- [ ] נשמר פלט סימולטור תקין כחלק מחבילת ההגשה.
- [ ] נבדקים גם הפלטים המודפסים הנדרשים בתהליך הרישום.

## 8. Migration

- [ ] migration מ־localStorage לשרת הוא idempotent.
- [ ] הפעלה חוזרת אינה יוצרת לקוחות כפולים.
- [ ] הפעלה חוזרת אינה יוצרת מסמכים כפולים.
- [ ] מסמך קיים אינו מקבל מספר חדש בטעות.
- [ ] כשל באמצע migration ניתן לזיהוי ולהשלמה בטוחה.

## 9. Release gate

לפני הגשה רשמית יש לקבל PASS לכל סעיפי P0, להריץ build/typecheck/lint/tests, לבצע בדיקה מקצועית של רואה חשבון/יועץ מס ומומחה מערכות מידע, ולהריץ את קובץ ה־Uniform Format בסימולטור הרשמי של רשות המסים.
